# 推荐候选项评分与解释方法

## 统计口径

候选项只使用本地扫描得到的可观测信号：笔记路径、创建/修改时间、字数、标签、任务、链接、文件夹和主题归属。报告中的 `reason` 是从结构化 `reasons[]` 派生的短摘要，`reasons[]` 中每一项都必须带有源笔记、相关笔记或统计字段，方便用户回到原始材料复核。

入链和出链来自 Obsidian 已解析链接；在非 Obsidian 环境中使用 Markdown wikilink 解析结果。字数按当前项目的 Markdown 清理和 CJK 计数逻辑统计。主题来自 frontmatter、标签、文件夹和本地回退聚类，不代表人工确认过的主题体系。

## 阈值

当前候选生成沿用已有确定性阈值，不新增推荐模型：

- 最近更新：距离生成时间不超过 30 天。
- 沉睡核心笔记：至少 2 个入链，且超过 90 天未更新。
- 长笔记/输出候选：正文至少 300 字词，并结合链接、主题或增长信号判断是否值得复核。
- 跨主题桥接：连接到至少 3 个主题，且存在真实出链。
- 孤立潜力：正文至少 300 字词，且没有入链或出链。

这些阈值只是复核入口，不表示真实价值、重要性或优先级结论。

## 排序

排序仍使用既有候选分数：核心、近期活动、桥接、增长、输出候选、沉睡维护和孤立潜力等信号会累积分数；字数、入链、出链和跨主题数量作为加权补充。分数相同后按入链、字数和路径排序，保证同一批输入可以稳定生成同一顺序。

解释理由的展示顺序是确定性的：链接和跨主题证据优先，其次字数、任务、标签和时间类信号，最后用路径和文案排序打平。

## 过滤边界

扫描范围来自用户设置：

- `includeFolders` 决定只扫描哪些文件夹；为空时扫描全部 Markdown 文件。
- `excludeFolders`、`excludePatterns` 和默认排除目录会移除生成报告、模板、归档和附件等路径。
- `includeLinks` 关闭时不生成链接相关信号。
- `includeFrontmatter` 关闭时不使用 frontmatter 标签或主题。
- `includeTasks` 关闭时任务信号不会进入统计。
- `privacyMode` 是报告和 AI 上下文的隐私边界；统计仍只来自本地扫描结果。

如果过滤配置漏掉了重要文件夹，候选项和解释也会缺失对应证据。

## 隐私

候选解释不调用外部服务。AI 增强只能在已有本地证据上改写展示文案，不能发明新理由。启用 AI provider 时，发送内容应受用户过滤设置和隐私模式约束；未进入扫描范围的笔记不会成为候选理由。

## 已知限制

- 统计信号不等于真实价值；它们只说明“值得复核的可观测原因”。
- 链接质量无法从数量直接判断，入链和出链可能包含历史遗留或低价值引用。
- 字数阈值偏向已有材料，可能漏掉短但关键的笔记。
- 主题归属来自本地规则，文件夹和标签设计会影响跨主题判断。
- 修改时间只能说明文件被更新，不能说明内容是否真的推进。
- 任务统计只反映 Markdown 中可解析的任务项，不覆盖外部任务系统。
